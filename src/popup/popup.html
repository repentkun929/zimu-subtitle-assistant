字幕行为

直接决定字幕延迟：延迟 ≈ 分块秒数 + 识别耗时。默认 6 秒（约落后 7~10 秒）。 觉得字幕跟不上语音就调小，但请求次数和费用会增加。

打开后不再等一块录满，而是每 1~2 秒连续投喂；服务端把尚未定稿的音频反复解码， 只把「连续两次结果一致」的部分定稿发出来。延迟可从约 6 秒降到 1~2 秒， 代价是 CPU 占用明显上升。云端供应商按次计费（反复解码等于反复收费）， 所以只对本机服务生效；服务端不支持时会自动退回上面的分块模式。

每次投喂的音频秒数。调小更灵敏但更费 CPU，调大反过来。默认 1.6 秒。

字幕条距视频底边的位置。默认 6%，就是贴在画面下方、和播放器底栏同一高度； 想再低就拖到 0（最低仍会留出一个字号的高度，避免大字贴边被切）。

字幕背后那块黑底的浓度。拖到 0 就是完全透明，只剩文字本身 （文字自动加描边阴影，浅色课件上也看得清）。默认 72%。

打开后一句话会一个字一个字地冒出来，而不是整句一下全出现。 节奏跟着这句话自己的语速走：6 秒说完的句子就花 6 秒打完， 说完停留约 1.5 秒后消失，接着打下一句。

收起后悬浮窗会滑到视频侧边、只在边缘留一条窄条，点它即可展开—— 和游戏助手一样。这样底部的字幕和悬浮窗就不会互相遮盖了。 面板上也有一个「收起」按钮，随时可以收起来。

「唤出面板」用于视频页面上找不到悬浮球时手动唤起。 若提示无法通信，说明该页面的内容脚本还没加载——刷新页面（F5）再试。

没有 API Key 怎么办？/ 该选哪个模型？

只想尽快用上、又不想占本机资源：选「硅基流动 · Qwen3-ASR-1.7B」。
去 cloud.siliconflow.cn 注册 → 控制台「API 密钥」建一个 sk- 开头的 Key → 粘贴到上面的框里 → 点「测试连接」。
硅基流动把语音识别类模型标为免费，这一档目前不花钱。

不想把 Key 放进浏览器：用本仓库自带的本地中继，Key 存在本机配置文件里， 扩展这边留空即可。启动命令：node tools/server/relay.mjs，然后供应商选「本地中继」。

不想联网：选「本地 Whisper」，但模型会跑在你自己电脑上，占 CPU/内存。
