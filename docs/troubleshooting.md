# 排错指南

按**现象**查。每一节都先给一条"30 秒判断法"，判断出问题在哪一层之后再往下深挖。

排查问题的通用第一步：**打开视频页面 → 按 F12 → Console 标签**，然后开启字幕。
如果设置里开了"输出调试日志"，控制台会打印每块音频的时间、大小和识别结果，
绝大多数问题看一眼日志就清楚了。

---

## 1. 页面上根本看不到悬浮按钮

**30 秒判断法**：在视频页面的 Console 里输入 `__ZIMU__`，回车。

- 显示 `undefined` → 扩展没注入到这个页面
- 显示一个对象 → 扩展已注入

**如果显示 undefined，按顺序排查：**

1. `chrome://extensions` 里确认扩展已启用、没有报错（红色"错误"按钮）
2. 确认加载的是 **`dist`** 目录而不是项目根目录
3. 改动过源码？重新执行 `node tools/build.mjs`，然后在扩展页点**刷新**
4. 页面是安装扩展之前就打开的 → 刷新页面（内容脚本只在页面加载时注入）
5. 用无痕窗口测试：如果无痕里能用、正常窗口不能用，说明是别的扩展或企业策略在干扰
6. 极少数平台会禁止扩展注入，检查该平台是否有企业策略限制

**如果显示对象、但看不到按钮**，再输入这两行：

```js
__ZIMU__.controller.overlay          // 有值说明叠加层已创建
__ZIMU__.controller.findVideo()      // 应该返回页面里的 video 元素
```

- `overlay` 是 `null` → 插件没找到视频（下一节）
- 两者都有值 → 按钮被页面样式挡住了、或跑到了可视区域外

**按钮被挡住**：字幕叠加层用的是固定定位 + 最高层级，正常不会被盖住。
如果页面上有别的悬浮控件正好在右下角，可以先把"显示悬浮按钮"关掉，
改用 `Alt + Shift + Z` 快捷键开关字幕。

### 插件找不到视频元素

`findVideo()` 返回 `null` 或返回的不是播放课程的那个元素，通常是因为：

- **视频在 iframe 里**：插件默认会注入所有子框架（`all_frames: true`），一般能覆盖。
  但如果那个 iframe 的地址是 `about:blank` 或 `blob:`，浏览器不允许注入
- **视频是异步插入的**：插件现在会立即探测 + 每 1.5 秒重试一次（持续约一分钟）
  + 监听播放器元数据 + 监听 DOM 变化，四重保险。如果你的页面需要更久，
  在视频开始播放后按 `Alt + Shift + Z` 手动触发即可
- **播放器不是 `<video>` 元素**：如果平台用 Canvas、Flash 或自绘播放器渲染画面，
  插件无法工作（无法读取其音频）。可以用 Console 里的
  `document.querySelectorAll('video').length` 确认页面到底有几个 video

> 历史提示：早期版本要等 `window` 的 `load` 事件才探测，而教学平台有大量资源，
> `load` 可能长时间不触发，导致"插件装好了但页面上什么都没有"。
> 现在改为立即探测 + 定时重试，不再依赖 `load`。

## 2. 开启了字幕，但一直没有任何字幕出现

**30 秒判断法**：打开 `test/demo-video.html`，点**运行环境自检**，看最后那行的音量判定。

- 自检页里也显示"几乎无声" → **音频采集问题**（见第 3 节）
- 自检页里显示"正常"，但你的网课页面不行 → **那个视频的跨域限制**（见第 3 节）
- 自检页正常，识别服务也返回文本 → **字幕渲染或时间轴问题**（见第 6 节）

**先确认这几件事：**

1. 视频**正在播放**吗？暂停状态不产生新块，这是刻意设计
2. 设置里点过**测试连接**并成功了吗？
3. 分块秒数设的是多少？设成 30 秒就要等 30 秒才出第一段
4. 有没有点过"授权访问该服务域名"？没授权时请求会被浏览器拦掉，
   状态栏会提示"还没有授权访问 xxx"

## 3. 提示"采到的音频疑似静音"或自检显示几乎无声

这是**最常见也最容易被误认为"识别不准"**的问题，根因是浏览器的同源策略。

### 为什么会这样

插件通过 `video.captureStream()` 读取视频元素里的音频。如果视频文件来自
**另一个域名**，且那个服务器没有返回允许跨域的响应头，浏览器会允许你播放，
但**不允许任何脚本读取其音频数据**。于是采集到的是纯静音——不报错，但什么都识别不出来。

### 怎么确认

看浏览器 Console 或网络面板里视频请求的响应头，有没有：

```
Access-Control-Allow-Origin: *
```

或者视频标签上有没有 `crossorigin="anonymous"`。两者缺一，且视频与页面不同域，就会静音。

### 怎么办

| 你的情况 | 解决办法 |
| --- | --- |
| 平台由你所在公司/学校维护 | 让运维给视频响应加上 `Access-Control-Allow-Origin`，这是最干净的解法 |
| 视频和你打开的页面**同域** | 不会触发这个限制。如果仍然静音，检查视频本身是否有声音 |
| 平台不受你控制 | 本插件无法绕过这条浏览器安全规则。替代方案见下 |

**替代方案**：用系统级的录音转文字工具（录制"系统声音"而非麦克风），
例如本地部署的 Whisper 桌面工具。这类工具不走浏览器，因此不受同源策略限制，
但需要在电脑上实时播放视频才能录制。

## 4. 报错 401 / 403 / 404 / 429

插件已经把常见 HTTP 错误翻译成了中文提示，对照处理即可：

| 状态码 | 含义 | 处理 |
| --- | --- | --- |
| 401 | Key 无效或没填 | 检查 API Key 有没有多余空格；本地中继方案下 Key 应该填在 `relay.config.json` 里 |
| 403 | Key 没有语音识别权限 | 去服务商控制台确认该模型已开通、账户有余额 |
| 404 | 接口地址不对 | `baseUrl` 要精确到 `/v1`，例如 `https://api.siliconflow.cn/v1`，**不要**自己加上 `/audio/transcriptions`（插件会自动拼） |
| 413 | 音频块太大 | 把"分块秒数"从 30 调小到 12 左右 |
| 429 | 触发限流 | 调大分块秒数（降低请求频率），或稍后再试 |
| 500 / 502 / 503 | 对方服务器或网关问题 | 多数是临时的；若是自建网关，检查网关到上游的连通性 |

**"连不上识别服务"**：先用浏览器直接打开你的 `baseUrl` 看能不能通。
如果选了 OpenAI 但网络不通，换国内服务，或改用本地中继。

### "某某服务不能用来做字幕识别"

如果你看到这条提示，说明你填的是一个**只有文本大模型、没有语音识别接口**的服务商。
插件会在你粘贴地址的当下就提醒，不会等你点了开启字幕才失败。

典型的就是 **DeepSeek**：它的 API 只有 Chat Completions、Responses API、FIM、
文件上传这些接口，模型也只有 `deepseek-flash` / `deepseek-v4-pro` 两个文本模型，
**没有音频转录接口**，也无法理解音频输入。同理还有 Moonshot、智谱
`open.bigmodel.cn`（智谱的语音识别是另一套独立服务，地址和协议都不同）。

**判断方法**：去服务商的 API 文档里搜 `audio/transcriptions`；
搜不到就再看它有没有 `chat/completions` 收 `input_audio`（“生成式 ASR”类模型走这条）。
两者都没有就不能用。

**怎么办**：换一个有语音识别接口的服务。推荐[硅基流动](https://cloud.siliconflow.cn/)
（`https://api.siliconflow.cn/v1`，模型选 `Qwen/Qwen3-ASR-1.7B`，国内可直连、标价免费），
或者阿里云百炼（`https://dashscope.aliyuncs.com/compatible-mode/v1` + `qwen3-asr-flash`），
也可以继续用本地中继。已有的 DeepSeek Key 在这个插件里用不上，但你的账号注册经验是通用的。

---

### "字幕里错字很多 / 像是把句子截断了"

两种原因，方向完全不同，先看日志分辨：

| 日志里的现象 | 真因 | 处理 |
| --- | --- | --- |
| 每块的「音频 ?.?s」只有 1~2 秒，而你设的分块秒数是 6 | 流式降级后**采集窗口没回滚**（已修复的缺陷，见 gotchas #34） | 重新 `node tools/build.mjs` 打包 + 刷新扩展 |
| 每块时长正常，但文字本身是「是他过他你」这种串 | **模型能力不足**（SenseVoiceSmall 只有 234M，且不利用上下文） | 设置里换「硅基流动 · Qwen3-ASR-1.7B」，错字大约减半 |
| 文字通顺但少了口语词、句子被“整理”过 | 换成了**生成式 ASR**（如 XingChenGSR）或语义规整型模型 | 换回 `Qwen3-ASR-1.7B`：字幕要逐字忠实，不要被改写 |

### "这个播放器的音频读不出来"

如果状态栏出现这句话，说明**音频采集方式**出了问题，插件已经自动在切换了：

| 诊断里的表现 | 含义 | 处理 |
| --- | --- | --- |
| `✓ 浏览器默认（127784 字节）` + `录到的音量：RMS=0.28` | **一切正常**，音频采集链路是通的 | 直接点开启字幕即可，先播放视频 |
| `✓ 浏览器默认（0 字节）` | 录音器能启动，但**一个音频字节都录不到** | 先确认视频在播放；仍为 0 则改用“抓取整个标签页声音” |
| 所有 webm 格式报 `NotSupportedError`，默认格式可用 | 正常现象：显式格式被拒，插件会自动用浏览器默认 | 无需处理 |
| `⚠ 诊断时视频处于暂停状态` | 暂停的视频不产生音频数据，**这次诊断结果不算数** | 点播放让视频出声，重新诊断 |

**一个高频误判**：诊断里那几行 `✗ audio/webm...` 看着像失败，其实**不是问题**——
说明这台机器上只有“浏览器默认”格式可用，而插件现在会逐组实测并自动选中可用的那组。
判断是否正常只看两点：**`✓` 那一行的字节数是否大于 0**，以及**有没有“录到的音量”这一行**。

### 出现"没有采集到音频内容"

说明那一块音频录出来是空的，最常见的原因是**视频还没开始播放**。
插件会跳过这种空块（既不上传也不报成"识别失败"），所以不会影响后续字幕。

**顺畅的操作顺序**：先让视频**正常播放并出声**，再点「开启字幕」。
如果先点开启字幕、后点播放，第一块会是空的（会被自动跳过），从第二块起才正常。

### 抓不到标签页声音

| 提示 | 原因 | 处理 |
| --- | --- | --- |
| “该标签页没有正在播放的声音” | 视频暂停 / 静音 / 还没开始播 | 先让视频真正出声，再点开启字幕 |
| “抓取标签页声音被拒绝” | 浏览器拒绝了请求 | 确认视频在播放；确认没有其他程序（如录屏软件）已占用该标签页音频 |

### 上传成功、但每一块都返回空文本

如果分块统计是 `上传 N 块，服务返回空 N 块`，同时 Console 里每块的体积很大
（例如 12 秒的块超过 1MB），那就是踩到了这个坑：

**`video.captureStream()` 不带参数时会同时返回视频轨和音频轨。**
如果把整个流交给 `MediaRecorder`，它会把**画面也一起录进去**：

| | 正常（只录音频） | 出错（连画面一起录） |
| --- | --- | --- |
| 12 秒的块 | 约 96KB（64kbps Opus） | 1.4 ~ 3.4MB（约 2.3Mbps） |
| 送到识别服务 | 正常识别出文字 | **解不出音轨，返回空文本** |

症状因此非常迷惑人：采集"一切正常"、上传"成功"，但**一条字幕都没有**。

**判断方法**：看 Console 里每块的 KB 数，12 秒的块超过 300KB 就不正常。
插件也会主动预警：超过 40KB/s 时状态栏会提示"疑似把画面一起录了进去"。

**修复方式**：采集时先剥掉视频轨，只把音频交给录音器
（见 `src/content/audio-source.js` 里的 `audioOnlyStream`）。
测试里有专门的回归用例守着这个行为，若又出现该症状先跑测试确认。

### "音频数据形态无法识别"

看到这条提示，说明音频数据在**从页面传到扩展后台**的路上丢了类型信息。
这是排查过程中真实踩过的一串坑，也是现在**改用 base64 字符串传输**的原因：

| 传输方式 | 实际结果 |
| --- | --- |
| Blob 对象 | 后台收到 0 字节 |
| ArrayBuffer | 后台收到"未知二进制形态(object)" |
| TypedArray | 同样被克隆降级成普通对象 |
| **base64 字符串**（现在） | ✅ 稳定可靠 |

原因是部分 Chrome 版本的 `chrome.runtime.sendMessage` **不保留二进制对象的类型**，
接收端拿到的是按索引存字节的普通对象，无法当二进制使用。
字符串则始终可靠，base64 只增加约 33% 体积（98KB → 131KB），完全值得。

**正常的日志长这样**：
```
[字幕助手] 第 0 块已上传识别（97KB，200.0s→212.1s）
收到音频：base64字符串(131252字符) → 还原后 98438 字节（第 0 块）
[字幕助手] 第 0 块识别到：……
```

如果"还原后"的字节数与内容脚本报告的**对不上**，或显示的是别的形态，
说明传输层又出问题了。`src/common/binary.js` 里有完整的形态处理与测试。

## 5. 本地中继服务相关问题

### 启动时报"还没有配置上游服务"

中继服务读取的是**它自己所在目录**下的 `relay.config.json`：

```
tools/server/relay.config.json
```

从 `relay.config.example.json` 复制一份再改。注意这个文件名不带 `.example`。

### 中继启动了，但扩展报连不上

1. 看中继那个终端窗口，请求进来时会打印 `[中继] ...`；没有打印说明请求没到，
   检查扩展里的地址是不是 `http://127.0.0.1:8787/v1`
2. 端口被占用了？换端口：启动时设 `$env:ZIMU_PORT=8899`，扩展里的地址也要同步改
3. 想看识别出的具体文字，用 `$env:ZIMU_LOG_TEXT=1` 再启动一次

### 我想把 Key 放在扩展里，不用中继

可以，直接把供应商改成云端服务填 Key 即可。两种方式的区别：
扩展里的 Key 存在浏览器的扩展存储中（本机可读），中继方案的 Key 存在你自己的配置文件里。

## 6. 有字幕，但时间对不上 / 内容重复 / 缺句子

### 时间对不上

字幕时间取自 `video.currentTime`，正常不会错位。如果你看到明显错位：

- 播放器是否用了倍速、快进、或自定义 seek？（插件会识别跳转并丢弃脏块）
- 控制台日志里每块的起止时间是否单调递增？把日志发出来便于定位

### 内容重复

相邻块重叠 1 秒，插件靠文本比对去重。极短的重复片段（如"好，我们继续"连着说两次）
可能被误判成重复而少显示一句。把**分块秒数调大**（例如 15）能减少这种边界情况。

### 缺句子

1. 句子是不是刚好处在块边界被切断了？调大分块秒数，让每块包含更完整的句子
2. 开着"输出调试日志"，看那一块的日志是**没有上传**还是**上传了但返回空**：
   - 没上传 → 被静音检测跳过了（阈值很保守，正常说话不会误判）
   - 上传了返回空 → 句子被切碎或音量太低，也试试调大分块秒数

### 字幕里出现 `[BLANK_AUDIO]`、`（掌声）` 之类

插件已经过滤了这些常见的模型幻觉标注。如果还有别的不认识的标注漏出来，
可以在 `src/common/transcript.js` 的 `ANNOTATION_WORDS` 里补一条。

### 字幕里出现和课程内容无关的短句（如「字幕製作人」「今天的视频就到这里」）

这是 Whisper 在**音乐/音效/纯音**上"编"出来的内容——不是识别不准，是它在非语音上
产生了幻觉。本地识别服务已按置信度过滤（见 `docs/gotchas.md` #32），但仍可能有漏网。

1. 确认服务是**新版本**：重启 `python tools\local-asr\server.py`，
   启动日志里应能看到 `流式识别：http://127.0.0.1:8788/v1/audio/stream`
2. 如果只出现在片头音乐处，属已知限制，可忽略
3. 频繁出现：把那段时间的 Console 日志发我，需要按真实数据调门限

### 流式模式下延迟没有明显改善

这是**预期内**的。流式的收益是「输出更连续、时间戳更准」，不是「首次字幕更早」——
Whisper 要攒够约 5 秒音频才敢定稿，这是模型属性。
实测数据与结论见 `docs/gotchas.md` #33。

- 若想更连续：把设置里「流式切片」从 1.6 调到 1.0
- 若想**几乎同步**：实时链路做不到，需要提前把整片转写好（见 `docs/roadmap.md` P0.5）
- 若 Console 出现「已退回分块模式」：说明本机服务不支持流式（旧版本）或连续失败，
  重启服务即可；也可以先关掉「流式识别」开关用分块模式顶着

## 7. 字幕盖住了播放器自己的控件或原生字幕

- 在页面悬浮面板里拖动**"位置"**滑块，把字幕往上挪
- 如果平台本身有字幕，插件不会自动关掉它。多数播放器的字幕开关在设置齿轮里，
  或者在播放器右下角的 `CC` 图标上

---

## 8. 全屏后字幕不见了

字幕层会自动挂到全屏元素下，正常应该正常显示。如果没显示：

- 退出全屏再进一次（切换时有极小的时序窗口）
- 确认是**播放器全屏**而不是浏览器全屏（F11）。浏览器全屏下插件同样有效，
  但如果页面重新挂载了 video 元素，请刷新页面重试

## 9. 修改了源码但看不到变化

必须走完这三步，缺一步都不生效：

```powershell
node tools/build.mjs          # 1. 重新打包到 dist
# 2. chrome://extensions 里点扩展的"刷新"图标
# 3. 刷新视频页面（内容脚本只在页面加载时注入）
```

改了 `background/service-worker.js` 之后，扩展页刷新会重载它；
但**已经打开的页面**里的内容脚本上下文会失效，表现为提示"扩展已重新加载，请刷新本页面"。

### 为什么第 3 步不能省（一个高频踩坑点）

内容脚本是**在页面加载时注入**的。你刷新扩展后，视频页面里跑的仍然是**旧的那一份脚本**，
它和扩展的联系已经断了。此时会出现两个很容易误导人的现象：

| 现象 | 真实原因 | 别被带偏 |
| --- | --- | --- |
| 点"开启字幕"说**"还没配置识别服务"** | 读配置失败（扩展失联），不是真的没配 | 不要反复去检查 API Key，**刷新页面**即可 |
| 改了设置但**好像没生效** | 页面里是旧脚本、读取的是旧配置 | 同上，刷新页面 |

插件现在会把这两种情况明确提示成"按 F5 刷新页面"，不会再说成"没有配置"。
如果悬浮球因为这些操作消失了，它也会在 8 秒内**自动回来**（插件会巡检自己是否还在页面上）。

**顺畅的操作顺序**：改设置 / 刷新扩展 → **刷新视频页面（F5）** → 播放视频 → 点「开启字幕」。

## 10. 想看更详细的运行日志

1. 设置里勾选**输出调试日志**
2. 视频页面 F12 → Console，过滤 `[字幕助手]`
3. 想看后台（service worker）的日志：`chrome://extensions` → 找到本扩展 →
   点 **Service Worker** 链接，会打开它自己的 Console
