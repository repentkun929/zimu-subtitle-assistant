逐个点评

Qwen3-ASR-1.7B首推
  • 中文误差率最低，课堂这种快语速 + 专业术语的场景优势最明显
  • 支持长音频一次转写，也支持时间戳（对面接扩展是加分）
  • 硅基流动把它标价免费；接口就是老的 /audio/transcriptions，换个下拉框即可
  • 中英混说不用手动切语言
XingChenASR-V3.2 / V3.2-Ultra方言场景才换
  • 中英 + 60 种方言混说，普通话朗读字准 97.25%，工业级打磨
  • 卖点是「高可读语义转写」——会自动删口头禅、理顺语序。 这对字幕恰恰是缺点：字幕应当尽量忠实原话，被“规整”掉的部分在观众看来就是漏字
  • 结论：讲师口音重或讲方言时值得换，普通普通话课堂不必
XingChenGSR-V1.0（生成式 ASR）做字幕请避开
  • 它会用大模型对识别结果做语义改写，输出的是「整理过的文本」而不是原话
  • 适合做会议纪要、摘要；不适合做逐字字幕
SenseVoiceSmall原默认
  • 免费、极快、资源占用小
  • 只有 234M，而且是非自回归模型、不利用上下文—— 每段音频独立识别，前面说的话帮不到后面。这就是「数据机 / 是他过他你」这类错字的来源
fnlp/MOSS-TTSD-v0.5 · FunAudioLLM/CosyVoice2不是识别模型
  • 这两个是 TTS（文字转语音），方向正好相反，做字幕用不上

阿里云百炼 vs 硅基流动

平台模型调用协议价格
硅基流动Qwen/Qwen3-ASR-1.7B /audio/transcriptions（上传文件）免费
阿里云百炼qwen3-asr-flash /chat/completions（音频放进 messages）新号 10 小时免费额度

两者其实同源（都出自 Qwen3-ASR 家族），选哪个看你手上有哪家的账号。 注意协议不一样：百炼没有 /audio/transcriptions 这个口子， 填错会得到一个很干净的 404 —— 插件的设置面板会把实际请求地址显示出来，方便对照。

一个必须说清楚的事：换模型解决的是「准不准」，不是「快不快」。
字幕延迟 ≈ 分块秒数 + 服务端排队耗时，跟你用多准的模型没有关系。 换模型之后，字幕该慢几秒还是慢几秒。
想要「几乎同步」，只有一条路：进页面时先把整段音频拿下来、提前转写， 播放时按时间查表显示。方案见 docs/roadmap.md 的 P0.5。
另外，你这次反馈的「错字漏字」其实主要不是模型的问题。
日志里「已退回分块模式」之后，每一块仍是 音频 1.6s —— 采集窗口的长度是开始录音前定死的（流式用 1.6 秒），降级时只改了标志位、没改窗口。 结果是一句话被反复从中间切断送识别，模型看不到完整上下文。这一处已经修好了。

怎么切换

  • 点浏览器工具栏的插件图标 → 展开设置面板
  • 供应商选「硅基流动 · Qwen3-ASR-1.7B（首推：中文最准，免费）」
  • 粘贴你的 API Key（控制台 → API 密钥）
  • 点「测试连接」，成功后再点「保存设置」
  • 回到视频页面按 F5 刷新——内容脚本只在页面加载时注入，不刷新等于没生效
